# Movement Networking

Issue #11 uses owner-authoritative movement for both roles. The owning player runs its
motor immediately, without waiting for Relay, while `OwnerNetworkTransform` publishes
the result on NGO's 30 Hz network tick. Remote instances interpolate position and yaw.

## Replicated state

- Position: X, Y, and Z.
- Rotation: Y only; camera pitch stays local.
- Scale: not synchronized.
- Transform deltas: unreliable, interpolated, and half-float compressed.
- Gameplay movement: no per-frame RPC. The only RPCs involved are NGO transform
  synchronization and the occasional targeted correction generated by NGO's
  `NetworkTransform.SetState` API.

The Kitchen server replaces each lobby diagnostic avatar with the Human or Cockroach
network prefab at the spawn marker assigned to that player's locked lobby seat.

## Host sanity checks

`MovementSanityMonitor` samples each player on the server and delegates policy to the
service-free `MovementSanityValidator`. It corrects:

- positions outside the Kitchen playable bounds;
- a single displacement greater than 4.5 metres; and
- movement sustained for more than 0.3 seconds above 175% of the role's configured
  maximum speed.

Transient sampling spikes do not cause corrections. Invalid state is returned to the
last accepted position and yaw. Human and Cockroach thresholds are derived from their
respective motor speeds, so normal movement and food slow-down remain inside the
envelope.

These checks are deliberately lightweight protection for a private casual game, not a
competitive anti-cheat system. A modified owner can still cheat while staying inside
the speed and bounds envelope. A future server-authoritative movement model would be
needed if the threat model changes.

## Windows Relay measurements

Measured on 2026-09-14 using four headless Windows development players over Relay. Each
player moved continuously for three seconds. `Total Bytes Sent` was sampled with Unity's
network profiler counter; values include NGO and Relay/session traffic present during
the sample, so they are a practical baseline rather than a transform-only payload count.

| Network profile | Listen-server host | Cockroach clients |
| --- | ---: | ---: |
| Baseline | 4.4 KB/s | 0.3-0.7 KB/s each |
| 40 ms one-way delay (~80 ms RTT) | 4.4 KB/s | 0.3-0.7 KB/s each |
| 75 ms one-way delay (~150 ms RTT), 2% loss | 3.6 KB/s | 0.3-0.6 KB/s each |

All four processes completed successfully in every profile, observed interpolated
remote movement, and stayed inside the Kitchen bounds. A separate four-player run
teleported Cockroach One to `(50, 5, 50)`; the host registered one violation and the
owner received the authoritative correction.

Reproduce the impaired run after making a development build:

```powershell
& .\Tools\Run-MovementRelayDiagnostic.ps1 `
  -OutputName rtt150-loss2 `
  -OneWayDelayMs 75 `
  -PacketLossPercent 2
```

Add `-TeleportViolation` to make Cockroach One attempt an out-of-bounds teleport and
require a successful host correction marker.
